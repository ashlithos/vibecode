What I'd build, and why

Decision Pick Reasoning
01 · Navigation 1A Three tabs Library is a stated goal, not a utility — it earns a permanent slot. History gets a home instead of leaking into Today.
02 · Today 2C Recovery-first The recovery strip is what makes a recommendation feel reasoned. Without it the app is a black box telling you to do things.
03 · Workout 3B Sets as rows Keeps one obvious action while leaving previous sets visible. 3C's cues are worth stealing — put them in a collapsible strip for exercises you haven't done before.
04 · Library 4A Chips + grid Scales and ships now. 4B is the better product — plan for it once there's real media, and reuse the same diagram for recovery.
05 · Detail 5A Single scroll Nothing hidden. Revisit 5C only once real demo media exists — pinning a grey placeholder is worse than not pinning.
06 · Session start 6B Adjustable default Two taps on a normal day, four when you're rushed, zero questions ever mandatory. Soreness stays optional and lives on the recovery strip.

The thread running through these picks

Every recommendation above resolves the same tension the same way: the app always has an answer ready, and never makes you produce one first. Questions become controls you may optionally reach for — the time selector, the soreness tap, the swap — rather than gates you pass through.

Three of these picks are deliberately the cheaper option with a better version noted behind it (4B's body map, 5C's pinned media, 3C's inline cues). All three are blocked on the same thing: real photography and demo loops. They're worth revisiting the week that media lands, and none of them require rework to get there.

None of this changes the data model in the approved plan — these are all rendering decisions over the same graph. So Phase 1 can start regardless of which way you go on any of the six.
